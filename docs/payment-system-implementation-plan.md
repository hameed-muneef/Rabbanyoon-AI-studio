# نظام الدفع — خطة التنفيذ والحالة

## الحالة الحالية

- السوق الأولي: مصر، والجنيه المصري هو العملة الأولية.
- XPay مرشح فقط؛ لا يوجد مزود معتمد أو تكامل مزود موثق.
- لا يوجد تحصيل أموال حاليًا: واجهة الدفع متوقفة، ومهايئ XPay يرفض العمليات، وEdge Function لا يسجل أي موفر Webhook.
- لا تُعد المنظومة جاهزة للإنتاج أو مختبرة مع Sandbox.
- قاعدة البيانات البعيدة: الترحيلات `202611010001`–`202611010008` موجودة؛ طُبقت `202611010006`–`202611010008` في 2026-11-01 وتم التحقق من بصماتها. فحوصات الكتالوج أكدت RLS وقفل المدفوعات المباشرة.

## ما نُفّذ

- [x] طبقة مستقلة عن المزود (`src/payments/types.ts`) مع عقد للمهايئات.
- [x] مسارات RPC آمنة لإنشاء الطلب والتحقق من الخطة والسعر والعملة، وقراءة الطلب، ومعالجة الحالات، والاشتراكات والفواتير.
- [x] منع إنشاء المستخدم طلبًا لحساب آخر، والتحقق من صلاحيات ملكية الطلب، وقصر تفعيل الدفع على المشرف/الخدمة.
- [x] معالجة تكرار مفاتيح الطلبات ومعرّفات أحداث Webhook، ومنع إعادة استخدام الحدث لطلب آخر.
- [x] حالات النجاح/الفشل/الإلغاء/الاسترداد، وانتهاء الطلب، وتجديد الاشتراك، والإلغاء مع استمرار الوصول حتى نهاية الفترة المدفوعة.
- [x] قيود RLS وإزالة منح الكتابة المباشرة للمستخدمين المسجلين على جداول الإعداد والخطط والفواتير؛ الترحيل `202611010005` مطبق عن بُعد.
- [x] واجهة Edge Function عامة ترفض الطلبات غير الصالحة وتفشل مغلقة عند غياب موفر موثق. لا يوجد تحقق توقيع أو تحويل أحداث لمزود حقيقي.
- [x] واجهة المستخدم لا تنشئ طلب دفع عند غياب تكامل موفر فعلي.
- [x] لوحة جاهزية إدارية تعرض الحالة باللغة العربية ولا تعرض أسرارًا. مؤشرات التحقق إدارية فقط ولا تفعّل التحصيل.
- [x] ترحيل `202611010006` مطبق: يضيف حالة إجمالية للجاهزية ويمنع تفعيل المدفوعات المباشرة.
- [x] ترحيلان `202611010007` و`202611010008` مطبقان: يعالجان منع إعادة الأحداث، وانتهاء الطلب، وتجديد الاشتراك، وإلغاء التجديد، وعدم خفض الحالة بسبب حدث فشل متأخر.
- [x] اختبارات PGlite وWebhook محلية تغطي مسارات الدفع المهيأة ومبدأ الفشل المغلق. الاختبارات لا تثبت التوافق مع أي مزود حقيقي.

## ما لا يزال معلقًا

- [ ] استلام وثائق API وWebhook الرسمية لمزود مصري مختار والتحقق من إصدارها.
- [ ] تنفيذ مصادقة المزود، وبدء Checkout خادمي فعلي، والتحقق من توقيع Webhook وفق مواصفة رسمية.
- [ ] تسجيل أحداث الدفع بعد التحقق من المصدر والطلب والمالك والمبلغ والعملة والمهلة.
- [ ] اختبار Sandbox حقيقي كامل، بما يشمل الدفع والرفض والإلغاء والاسترداد وإعادة المحاولة.
- [ ] اعتماد حساب التاجر وتوفير بيانات Sandbox والإنتاج من المزود.
- [x] تطبيق الترحيلات `202611010006`–`202611010008` والتحقق من بصماتها وسلامة جداولها وصلاحيات RPC وقفل الدفع المباشر.
- [ ] نشر الواجهة وEdge Function والتحقق من إعداد Webhook فعليًا.
- [ ] اختبار إنتاجي مضبوط بعد اعتماد المزود، ثم تفعيل إداري صريح عبر إعداد خادمي آمن.

## تصنيف الجاهزية

- **منفذ ومختبر محليًا:** هيكل RPC، قيود قاعدة البيانات في اختبارات PGlite، مسارات Webhook العامة، الواجهة ولوحة الجاهزية. كما أن الترحيلات 006–008 مطبقة ومتحقق منها في قاعدة البيانات البعيدة.
- **مختبر مع Sandbox:** لا شيء.
- **بانتظار بيانات التاجر:** مزود يتم اختياره واعتماده، ووثائق وبيانات Sandbox/الإنتاج الرسمية.
- **بانتظار اعتماد المزود:** نعم.
- **جاهز للإنتاج:** لا. لا يوجد Checkout مزود فعلي أو توقيع Webhook موثق أو اختبار Sandbox أو نشر نهائي.

### تحقق قاعدة البيانات البعيدة — 2026-11-01

- طُبقت الترحيلات `202611010006`–`202611010008` في معاملة واحدة، ثم طوبقت بصماتها مع سجل `private.schema_migrations`.
- تحقق وجود `payment_integration_settings` مع RLS، وعمود انتهاء الطلب وربط حدث Webhook بالطلب، وبقاء RPC التفعيل قابلًا للتنفيذ للمسجلين والخدمة، وبقاء `live_enabled=false` وقفل التفعيل الإداري خادميًا.
- استدعاء RPC الجاهزية بحساب إداري أعاد `integration_status=not_configured` و`signature_verification=not_implemented` و`live_payments_enabled=disabled`؛ لم يُهيأ أي مزود.
- **مصالحة بصمة `202611010002`:** يحتفظ سجل القاعدة ببصمة النسخة الأصلية المطبقة، بينما الملف المحلي بصيغة أحدث. أضيف استثناء دقيق في `scripts/database-migrations.mjs` يقبل فقط زوج البصمتين المتحقق منهما ولا يغير سجل القاعدة أو يعيد تنفيذ SQL؛ أي اختلاف لاحق عن بصمة الملف الحالية يظل مرفوضًا. يغطي ذلك اختبار `tests/database-migrations.test.mjs`.
- تطبيق مخطط قاعدة البيانات لا ينشر الواجهة أو Edge Function، ولا يثبت تشغيل مزود دفع.
