# خطة تنفيذ محرك الإشعارات والمنبهات الموحّد وتحسين واجهة المستخدم

> هذا الملف هو خطة التنفيذ الرسمية لميزة "محرك الإشعارات والمنبهات الموحّد + تحسين واجهة المستخدم" في مشروع الربانيون. يُحدّث مع إكمال كل مهمة. لا تُعتبر المهمة مكتملة إلا بعد اختبارها والتحقق منها.

## 1. أهداف المشروع

- إنشاء محرك إشعارات ومنبهات مركزي قابل لإعادة الاستخدام يخدم كل وحدات المنصة (القرآن، الأذكار، الصلاة، الأهداف، المهام، الدورات، الإعلانات الإدارية، إلخ).
- دعم التذكيرات الشخصية (أlarms) مع تكرار مرن (يومي، أسبوعي، شهري، تواريخ محددة).
- دعم إشعارات الصلاة والأذان مع أوقات قابلة للحساب والتخصيص لكل صلاة بشكل مستقل.
- مكتبة صوتية مركزية للأصوات والأذان مع معاينة وتحميل آمن للملفات المخصصة.
- مركز إشعارات محسّن مع تصفية، تاريخ، تعليم كمقروء، ولا تكرار.
- إعدادات إشعارات شاملة (عام، صلاة، منبهات شخصية، أذكار إسلامية، مكتبة أصوات، تاريخ الإشعارات، أذونات المتصفح).
- بناء المعمارية بحيث تكون جاهزة للتطبيقات المستقبلية (أندرويد، أي iOS) دون إعادة كتابة منطق العمل.
- تحسين واجهة المستخدم/تجربة المستخدم لجعل المنصة أكثر احترافية، أناقة، استجابة، وسهولة في الاستخدام (اللغة العربية RTL أولوية).
- الحفاظ على كل الوظائف القائمة وعدم كسر أي ميزة موجودة.

## 2. تقييم البنية الحالية

### ما موجود بالفعل (قائم ومختبر)
- جدول `public.notifications` مع RLS (المستلم فقط يقرأ إشعاراته).
- دوال RPC: `send_notification`, `list_notifications`, `mark_notification_read`, `mark_all_notifications_read`, `unread_notification_count`.
- دالة `private.notify()` ومُشغّلات (triggers) على جداول: `group_join_requests`, `course_registrations`, `tawasi_mentorship_requests`, `tawasi_mentors`, `teacher_applications`, `reports`, `admin_accounts`.
- مكون React `NotificationCenter.tsx` مع bell، تنبيهات، فلاتر، ترحيل، تعليم كمقروء.
- تفضيلات الإشعارات في `user_preferences.notification_preferences` (JSONB).
- أوقات الصلاة عبر AlAdhan API مع تخزين مؤقت في localStorage.
- تصميم CSS قائم (design-system.css) بألوان خضراء وثقيلة محايدة.
- PWA مع vite-plugin-pwa وتخزين مسبق للأصول.

### ما يحتاج إلى إضافته
- جدول `public.reminders` للتنبيهات الشخصية.
- جدول `public.notification_settings` لتفضيلات الإشعارات المفصّلة.
- جدول `public.notification_events` لتاريخ الإشعارات وحالة التسليم.
- جدول `public.audio_resources` لمكتبة الأصوات.
- جدول `public.device_tokens` للمستقبل (تطبيقات الجوال).
- دوال RPC جديدة: `create_reminder`, `update_reminder`, `delete_reminder`, `list_reminders`, `snooze_reminder`, `set_prayer_notification_preferences`.
- خدمات واجهة أمامية: NotificationService, SchedulerService, DeliveryService, AudioService, PlatformAdapter.
- مكونات React: NotificationSettings, PrayerNotifications, ReminderManager, enhanced NotificationCenter.
- تحسين HomeView (لوحة التحكم) لعرض أوقات الصلاة والتذكيرات القادمة.
- تحسين نظام التصميم (design-system.css) بألوان أكثر احترافية.

### القيود التقنية (موثقة)
- المتصفح لا يضمن تنفيذ التنبيهات في الخلفية مثل التطبيقات الأصلية؛ يجب توضيح هذا للمستخدم.
- لا يوجد WebSocket/Realtime؛ العداد غير المقروء يعتمد على الاستطلاع (polling) كل 30 ثانية.
- لا يوجد مزود دفع خارجي للإشعارات (VAPID مؤجّل).
- التطبيق الحالي ويب فقط؛ التطبيقات الجوال مستقبلية تحتاج لتسجيل رموز الأجهزة (device tokens).

## 3. التصميم الهندسي المقترح

### المكونات المنطقية (مفصولة عن منصة التوصيل)

```
src/notifications/
  types.ts          - أنواع البيانات (Reminder, NotificationPreference, AudioResource, DeviceToken)
  service.ts        - NotificationManagementService (CRUD للتذكيرات والإشعارات)
  scheduler.ts      - AlarmAndSchedulingService (جدولة، تكرار، مناطق زمنية، تأجيل)
  delivery.ts       - NotificationDeliveryService (توصيل عبر المتصفح، التطبيق، المستقبل)
  audio.ts          - SoundAndAudioManagementService (مكتبة الأصوات، معاينة، تحميل)
  adapters.ts       - PlatformNotificationAdapters (ويب، أندرويد مستقبلاً، أي iOS مستقبلاً)
```

### نموذج البيانات (قاعدة البيانات)
- `public.reminders` (id, user_id, title, description, scheduled_at, recurrence, days_of_week, start_date, end_date, sound_id, category, linked_goal_id, linked_task_id, enabled, snooze_until, created_at, updated_at)
- `public.notification_settings` (user_id, global_enabled, categories JSONB, prayer_settings JSONB, reminder_settings JSONB, quiet_hours JSONB, dnd_enabled, updated_at)
- `public.notification_events` (id, notification_id, user_id, delivered_at, channel, status, error)
- `public.audio_resources` (id, title, kind, url, duration, is_default, is_uploaded, uploader_id, created_at)
- `public.device_tokens` (id, user_id, token, platform, created_at, last_used_at)

### واجهة برمجة التطبيقات (RPCs)
- `send_notification` (موجود) - 확장 للنوع الجديد `prayer`, `reminder`, `worship`, `goal`, `task`.
- `create_reminder`, `update_reminder`, `delete_reminder`, `list_reminders`, `snooze_reminder`, `toggle_reminder`.
- `set_prayer_notification_preferences`, `get_prayer_notification_preferences`.
- `register_device_token`, `unregister_device_token`.
- `mark_notification_read`, `mark_all_notifications_read` (موجودان).

## 5. معايير القبول النهائية

1. محرك الإشعارات مركزي وقابل لإعادة الاستخدام.
2. يمكن للمستخدم إنشاء وإدارة المنبهات الشخصية.
3. يمكن للمستخدم إعداد إشعارات كل صلاة بشكل مستقل.
4. أوقات الصلاة تُحسب باستخدام طرق قابلة للتكوين.
5. يمكن للمستخدم اختيار ومعاينة أصوات الإشعارات.
6. تحميل الصوت المخصص يعمل بشكل آمن.
7. تفضيلات الإشعارات تُحفظ بشكل صحيح.
8. مركز الإشعارات متكامل مع النظام الجديد.
9. الجدولة تتعامل مع التكرار، المنطقة الزمنية، وتوقيت الصيفي بشكل صحيح.
10. التنفيذ على الويب يحترم قيود المتصفح الفعلية.
11. المعمارية تدعم تطبيقات أندرويد وأي iOS مستقبلية.
12. الواجهة أكثر احترافية وأسهل في الاستخدام.
13. اللغة العربية RTL والإنجليزية LTR تعملان بشكل صحيح.
14. الوظائف القائمة تبقى سليمة.
15. الوظائف الأساسية اجتازت اختبارات الانحدار والأمان الفعلية.

## 6. القيود المعروفة

- لا صوت أذان مرخص مدرج في المستودع (يجب اختيار أصوات مرخصة قبل تضمينها).
