# Arabic Hadith Data Source Evaluation

**Research date:** 2026-11-02

**Scope:** Complete Arabic texts of Sahih al-Bukhari and Sahih Muslim for possible local storage in Al-Rabbaniyyun.

**Decision:** **NO-GO for production import from every source evaluated.** No candidate currently combines proven redistribution rights, a traceable printed edition and numbering crosswalk, complete records, and reliable chapter linkage.

This is a technical and source-rights assessment, not a religious authentication or legal opinion. No Hadith data was imported into the production database or deployed. Earlier research downloads were confined to temporary storage and removed after validation. The workspace's local `data/ara-bukhari.json`, `data/ara-muslim.json`, and `data/editions.json` files were inspected in place, then used to generate local `public/hadith/` preview assets at the owner's request; this does not clear public deployment or redistribution rights.

**Project preference (2026-11-02):** The project owner selected AhmedBaset/hadith-json as the preferred candidate for further evaluation and preparation only, then provided the fork [hameed-muneef/hadith-json at commit `70b83d6d21995bb32f8d7271cd75501be5a922a7`](https://github.com/hameed-muneef/hadith-json/tree/70b83d6d21995bb32f8d7271cd75501be5a922a7) and authorized its use. The fork is an upstream commit, not a separately licensed dataset. This authorization permits project-side evaluation/preparation of the fork; it does not establish rights to the Sunnah.com-derived content, resolve the missing content license, or approve an import.

**Publication request follow-up (2026-11-02):** The project owner requested production use and approved publication, but no written permission from Sunnah.com or another actual rights holder was provided. The response supplied was the README's generic contribution invitation, which does not grant content/database rights. Production import remains **NO-GO**.

**Local data folder follow-up (2026-11-02):** The owner asked to use the Hadith files now present in `data/`. These are Fawaz Ahmed hadith-api Arabic editions, not files from the AhmedBaset fork. A development preview now reads generated static assets from this source, after omitting records with empty Arabic text. Their pinned-source metadata, omissions, unknown author/source fields, and unresolved content rights are documented below; the preview is not an approval to deploy, redistribute, or import the collections into production.

## Dorar Hadith API: approved-search model, not a dataset

The official [API service page](https://dorar.net/api-services) advertises machine-readable JSON services for researchers, organizations, and applications. The dedicated [Hadith search endpoint](https://dorar.net/api-services/hadith) documents `GET /api/v1/hadith/search`. Access requires a token issued after manual review of an access request stating the applicant, purpose, beneficiaries, and providing a preview/review access to the resulting product.

The documented search parameters are required query `q` (2–200 characters), `limit` (1–20, default 15), `degree` (all/one of four documented categories), `match` (`any`, `all`, or `phrase`), and `highlight`. A result includes `text`, `narrator`, `muhaddith`, `source`, `page_or_number`, `grade`, `url`, and links to commentary/similar records. No collection-wide endpoint, offset/page parameter, Arabic-only filter, explicit diacritic guarantee, or full Bukhari/Muslim export is documented. The endpoint returned HTTP 401 without a token; no token was requested or used.

The official [API terms](https://dorar.net/api-services/terms) materially constrain use:

- Attribute each text to **Dorar Al-Sunniyyah**, keep its returned `url` visible/clickable, and do not alter or abbreviate the grade.
- Do not display a hadith text from this service without its accompanying encyclopedia grade.
- Access is limited to the specific approved product. Bulk scraping/download, reconstructing the encyclopedia, full-database storage, sublicensing, and redistribution are prohibited.
- Response caching is allowed only for performance and for a maximum of 24–48 hours; cached data must be refreshed and deleted if access ends.
- The token is private to the approved applicant, must remain server-side, and must not be embedded in client applications or public source code.
- The published limit is 60 requests per minute, subject to change. Dorar may revoke access, and requires review access to the product before publication.
- Terms prohibit selling the live data or charging an exclusive access fee for Dorar's otherwise free content. They do not grant ownership of the returned text/database.

The encyclopedia's [methodology](https://dorar.net/article/77) explains that its focus is on hadith judgments transmitted from hadith scholars, with the original judgment attributed to its speaker. It says Bukhari/Muslim narrations are included in the encyclopedia context, while the methodology limits separately written entries to reports criticized by hadith scholars. This is not a promise that the search API exposes every narration in either collection as an exhaustive, exportable collection. This interpretation should be confirmed with Dorar when requesting access.

**Assessment:** Dorar may be the best fit among the reviewed services for a curated, online hadith lookup that shows scholarly grading and provenance, subject to token approval, product review, and strict compliance with its terms. It is not a suitable source for the project's stated goal of importing complete Sahih al-Bukhari and Sahih Muslim into a local database, enabling offline access, or republishing a local copy. Do not query or cache it as a way to reconstruct either collection.

## Validation results

### Open Hadith Data: JSON and SQLite

The release JSON parsed successfully. The SQLite database passed `PRAGMA integrity_check` (`ok`) and `PRAGMA foreign_key_check` (no rows); all target hadith rows resolve to a book in the same collection. Its `collections`, `hadiths`, `books`, and `chapters` tables contain 18, 46,891, 607, and 14,377 rows respectively. The 18 metadata entries include 17 hadith collections and a separate Hisn al-Muslim collection; the `duas` table contains 268 rows. Counts for both target collections match between the JSON and SQLite snapshots.

| Collection | Hadith rows | Books | Chapter metadata rows | Unique references | Observed numbering | Numbering gaps |
|---|---:|---:|---:|---:|---|---|
| Sahih al-Bukhari | 7,252 | 97 | 3,570 | 7,252 | `1` through `7563` | 311 absent integer references in that range |
| Sahih Muslim | 3,087 | 56 | 1,332 | 3,087 | `8a` through `3033a`; 1,971 references include a letter suffix | 16 absent integer bases from 8 through 3033, ignoring suffixes |

These are observed reference gaps, not a claim that the same number of narrations is missing: numbering may combine, split, or repeat narrations, and no printed-edition crosswalk was verified. The project README reports the same row counts, but counts alone do not prove completeness.

Additional checks:

- Neither collection has an empty Arabic field, a record without Arabic script, or a record without at least one Unicode combining mark. This only proves that some diacritic marks occur in every record; it does **not** prove complete vocalization of every word.
- No duplicate references were found. Exact repeated Arabic-text values were found in two Bukhari groups and one Muslim group. Repeated wording may be legitimate and is not by itself evidence of duplicate records.
- Two Bukhari texts contain a literal `?`, at references `Sahih al-Bukhari 3962` and `Sahih al-Bukhari 6321`.
- The `books` foreign key is populated, but `chapter_number` is NULL on all 7,252 Bukhari and all 3,087 Muslim hadith rows. The separate chapter names therefore cannot be joined to individual narrations using this release's hadith records without an independently verified mapping.
- Muslim's 16 absent integer bases are `1489`, `1698`, `1824`, `2293`, `2483`, `2503`, `2828`, `2931`, and `3007`–`3014`.
- SQLite stores `hadith_number` as text, which is necessary for Muslim suffixes such as `8a`; consumers must not cast it to an integer.

The release also advertises CSV, but the CSV asset was not downloaded or independently validated. JSON and SQLite were the formats structurally validated.

### AhmedBaset/hadith-json: JSON

Both pinned v1.2.0 JSON files parsed successfully. The Bukhari file has 7,277 narrations and 97 chapter/book metadata entries; the Muslim file has 7,459 narrations and 57 entries. `idInBook` is continuous from 1 through each file's record count, but the README schema documents `id`, `chapterId`, `bookId`, `arabic`, and `english`—not a printed reference. The internal sequence must not be mistaken for canonical hadith numbering.

- No Arabic field was empty or without Arabic script; every record had at least one combining mark. As above, this does not establish full diacritization.
- Two Bukhari records contain `?`; no Muslim record did in the downloaded snapshot.
- Two distinct repeated Arabic-text values were found in each collection. This alone does not establish erroneous duplicate narrations.
- The differing row counts versus Open Hadith Data—25 more Bukhari rows and 4,372 more Muslim rows—cannot be reconciled by a safe record-level crosswalk from the available identifiers.

### The Hadith Project: Bukhari JSON books

The pinned repository contains 97 per-book JSON files (`001.json` through `097.json`), separate from the 16-record prototype API index. All 97 files parsed successfully. Their combined 7,580 narration records match the `total: 7580` in the Bukhari collection metadata; this establishes internal structural consistency, not scholarly completeness.

- All 7,580 `textAr` values were nonempty and contained Arabic script and at least one combining mark. No record contained a literal `?`; full vocalization was not established.
- All 7,580 `n` references were unique. The values span integer bases 1–7563; 26 are decimal subreferences (`.2` or `.3`). Nine integer bases are absent: `5710`, `5711`, `5712`, `5774`, `5775`, `6074`, `6075`, `6174`, and `6175`.
- There are 97 Arabic/English book-name records. No per-narration chapter/bab field was found.
- Narration records include structured `chain` data (`names`, `sighas`, and status) and `sources` data. The source fields point to OHD/reference numbers; the project About page independently identifies OHD as the Arabic-text source.
- 289 distinct exact `textAr` values repeat. These may represent legitimate repeated narrations and are not, on their own, evidence of duplicated records.

### The Hadith Project and Sunnah.com

- The pinned The Hadith Project API response is marked `prototype`, contains 16 index entries, and has license metadata directing readers to project licensing and each collection's sources. Fourteen entries have `thp:bukhari:` IDs; none has a `thp:muslim:` collection ID. Each links to an individual JSON record. The repository's Bukhari book files are a separate, substantially larger dataset; neither is a Muslim export.
- Its Bukhari metadata names Muhammad Fu'ad Abd al-Baqi numbering, as used in *Fath al-Bari* and on Sunnah.com. This is useful provenance, but the absent bases, suffixes, missing chapter links, and lack of printed-page comparison prevent a completeness claim.
- Sunnah.com's published developer page says its API exposes only a portion of the data while manual checking is completed, requires an API key, and has no offline dump available yet. The pinned OpenAPI spec uses an `X-API-Key` header and documents paginated results with a maximum `limit` of 100.
- No API key was requested or used. No scraping or bulk retrieval from Sunnah.com was performed.

### Cross-source comparison and printed editions

OHD and AhmedBaset both identify Sunnah.com as their source; they are therefore not independent textual witnesses. Their counts, schema, and identifiers differ substantially. A deliberately coarse comparison normalized each unique Arabic string to NFD, removed combining marks, tatweel, whitespace, punctuation, and symbols, then normalized to NFC. It found 25 shared distinct strings for Bukhari and 16 for Muslim. This is **not** a match rate or completeness score: AhmedBaset has no verified crosswalk to OHD's references, and the sources can differ in record boundaries, text versions, and numbering. No records were merged.

The Hadith Project Bukhari `sources.ref` values mapped to 7,251 of its 7,580 records by reference number after removing the OHD collection prefix. Of those 7,251 common-reference pairs, 2,002 `textAr`/OHD Arabic-text pairs were identical after the same conservative normalization. The other pairs may reflect text-version differences, segmentation, or editorial changes; this automated comparison is not an authenticity judgment and requires manual review.

No candidate was compared line-by-line with a scanned printed edition in this research. The explicit Fu'ad Abd al-Baqi numbering statement in The Hadith Project's Bukhari metadata is the clearest edition/numbering declaration. Sunnah.com says its Arabic and English numbering may differ and that unified references are being added gradually. OHD's Bukhari references and Muslim letter-suffixed references can be retained as source strings, but their printed edition and page-level provenance were not established here. AhmedBaset's internal `idInBook` is not adequate evidence of a printed numbering convention.

## Recommendations

- **Bukhari:** No production-approved source. The Hadith Project's 97 pinned JSON book files are the strongest *traceability candidate*: they explicitly name Fu'ad Abd al-Baqi numbering, include structured chains, and contain a source-reference field. They remain **conditional research data only** because the root-level data license scope is unclear, upstream OHD/Sunnah.com rights are unresolved, nine integer bases are absent, chapter-level headings are not linked, and no printed pages were checked. OHD remains a useful alternate structured snapshot, with its own separate rights and mapping issues.
- **Muslim:** No production-approved source. Open Hadith Data is the only downloaded candidate with explicit source-reference strings and a SQLite export, but its license provenance, 16 absent integer bases, 1,971 suffix-bearing references, and missing chapter assignments prevent approval. AhmedBaset's 7,459-row count cannot be verified against a printed numbering scheme.
- **AhmedBaset (project choice):** Continue technical preparation using the user's fork pinned at `70b83d6d21995bb32f8d7271cd75501be5a922a7`; it is upstream content, not a distinct licensed dataset. The fork's Arabic records match v1.2.0, while some English fields differ. Before any import, obtain written content/database reuse permission from the relevant rights holders, establish the exact source and printed numbering/edition crosswalk, and reconcile collection completeness. The owner's permission to use their fork does not waive these gates.
- **Local `data/` preview:** The UI uses the locally provided Fawaz Ahmed hadith-api files, omitting blank Arabic records and reporting their count. This is a development preview, not confirmation of completeness or redistribution rights; do not deploy the bundled `public/hadith/` assets until the rights and edition gates are resolved.
- **Dorar:** Prefer it over scraped JSON repositories only if the feature is **online hadith search with the encyclopedia's grade and attribution**, and Dorar approves the product/token. Do not choose it as the full local Bukhari/Muslim dataset: its documented API is query-only, capped at 20 hits per call, and its terms expressly prohibit bulk extraction/full-database storage and redistribution.
- **Sunnah.com:** Ask for written authorization and a complete offline snapshot, including explicit permission for local storage, public display, and redistribution in this platform; request the exact Arabic source/edition, numbering rules, completeness guarantees, and correction/version policy.
- **No automatic merge:** Do not combine records from OHD, AhmedBaset, The Hadith Project, or a future Sunnah.com export. Any future comparison must use an authoritative, reviewed crosswalk and retain source provenance per record.

## Go/no-go and next steps

**NO-GO for production import or deployment of the bundled Hadith corpus:** Do not import any candidate into the production database or deploy the local `public/hadith/` preview assets until rights, edition, and completeness gates pass. Do not use the Dorar API to reconstruct a local corpus. A separately scoped online Dorar search feature may be considered only after the access request is approved and the application meets its terms. The database gate requiring approved rights and complete import remains unchanged.

Before any future import:

1. Obtain written rights for commercial storage, display, backup, and redistribution of the Arabic text and database, from the actual rights holder/source.
2. Select a named printed edition and editor for each collection; specify how repeated narrations, compound references, suffixes, and numbering gaps map to that edition.
3. Obtain an authorized complete dataset and a correction/version manifest; verify book/chapter links and compare the text to an identifiable printed copy.
4. Re-run structural, text, numbering, duplicate, placeholder, and checksum checks against that approved snapshot. Keep each collection and source separate; do not merge.
5. Only after these gates pass, propose a separate implementation/import plan for review. `QUR-013` remains blocked in [the implementation plan](./RABBANIYYUN_IMPLEMENTATION_PLAN.md).
